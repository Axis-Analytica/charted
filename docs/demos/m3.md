# Milestone 3 checkpoint: real modeling

Run `bin/checkpoint m3`. It builds charted (and the DAX editor's WebAssembly), creates a
fresh sample at `~/Work/charted-checkpoints/Harbor & Pine`, runs the scripted flow in
Chromium (screenshots in `~/Work/charted-checkpoints/m3/`), opens the project the tests
built in the real window (`m3-window-built.png`, `m3-window-model.png`,
`m3-window-column-formula.png`), then opens the app with the fresh sample.

1. **The star.** Press `Ctrl+3` (or the third icon in the left rail) for the **Model
   view**. The tables are laid out as a star: Sales and Targets in the middle, the
   tables that filter them either side. Each line joins the two key columns, with `1`
   and `*` at its ends and an arrow showing which way filters flow; the
   Sales[ShipDateKey] → Date relationship is **dashed** because it is inactive. The
   list on the right has every relationship. Scroll or drag the background to pan,
   `Ctrl`+scroll to zoom, `Ctrl+0` to fit. Drag a card by its header to move it (one
   undo step; positions are saved with the report). *Arrange* lays the cards out again.
2. **Create the Targets relationship.** Drag **Targets → StoreKey** onto **Store →
   StoreKey**. The dialog counts the keys on both sides ("40 distinct of 1,825 rows ·
   41 distinct of 41 rows · every key has a match") and suggests *Many to one*. Create.
3. **Set Both — and see why Power BI refuses it too.** Double-click the new
   relationship (on the diagram or in the list), set *Cross filter direction* to
   *Both*, Save. charted refuses with "this would give filters two active paths from
   'Date' to 'Sales'…": with Targets filtering Store, Date could reach Sales directly or
   through Targets → Store. Make one relationship inactive, or keep it single.
   (Both works wherever it is unambiguous; its semantics are tested against the
   reference interpreter.) The *⋯* on a card marks it as a date table.
4. **Autocomplete and squiggles.** `Ctrl+1`, click the page, `Ctrl+M`. The formula bar
   is now a DAX editor: type `Ship Sales = calcul` and pick *CALCULATE* (Enter or Tab);
   type `[`, `Sales[` or `'` for measures, columns and tables. Inside a call the
   parameters are shown, the current one highlighted. Hover a function, column or
   measure for details. Type a misspelt column (`Sales[Amont]`): it is underlined and
   the problem is spelled out under the editor. *Format DAX* (✨ wand, or
   `Shift+Alt+F`) lays the formula out the DAX Formatter way. Enter commits;
   Shift+Enter adds a line.
5. **USERELATIONSHIP and ALL side by side.** Create
   `Ship Sales = CALCULATE ( [Total Sales], USERELATIONSHIP ( Sales[ShipDateKey], 'Date'[DateKey] ) )`
   and `All Years Sales = CALCULATE ( [Total Sales], ALL ( 'Date' ) )`, then a *Table*
   with Date → *Year*, *Total Sales*, *Ship Sales* and *All Years Sales*: ship-date sales
   differ slightly from order-date sales each year; all-years sales repeat the grand
   total on every row.
6. **A RELATED calculated column.** `Ctrl+2`, pick **Sales**, *New column*, and write
   `List Value = Sales[Quantity] * RELATED ( Product[ListPrice] )`. Commit: charted
   works out the type (Decimal number), computes the values for all 245,387 rows and
   shows the new column; the status bar counts its distinct values and *Column
   statistics* profiles it. Click any calculated column to edit its formula; undo
   recomputes it. It can be used in visuals like any column.
7. **Export to Power BI.** *File → Export Power BI project…*, choose a folder. It holds
   `Harbor & Pine.pbip`; open
   `Harbor & Pine.SemanticModel/definition/tables/Sales.tmdl` to see the measures, the
   calculated column and an M partition generated from the load steps (files are read
   relative to a `SourceFolder` parameter in `expressions.tmdl`). The same from a shell:
   `target/debug/charted-headless export pbip "<project>" <folder>`.
8. **Ossie round trip.** *File → Export Apache Ossie model…*, then *File → Import
   Apache Ossie model…* and pick the same file: "0 differences". Edit a measure's name
   in the YAML and import again to see the difference listed before you import it
   (one undo step). From a shell: `charted-headless export ossie "<project>" m.yaml` and
   `charted-headless import "<project>" m.yaml --dry-run`.

`docs/dax-support.md` lists the 42 functions charted evaluates and the 87 it recognises
(they autocomplete and show signatures, and using one says it is not supported yet).
