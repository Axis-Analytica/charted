# v1.4 demo: interop depth (roles, View as, the theme editor, what-if parameters)

Open the sample (*Explore the sample*) in the app (`bin/dev`) or in a browser against the
dev server. The scripted versions are `ui/e2e/v14roles.spec.ts`,
`ui/e2e/v14theme.spec.ts` and `ui/e2e/v14params.spec.ts`
(`cd ui && npx playwright test e2e/v14roles.spec.ts`;
`CHARTED_SHOTS=<dir>` saves screenshots).

## Roles and View as (row-level security)

1. **Manage roles.** Add a page with a card (Total Sales) and a Store → Region slicer.
   In the report toolbar, the shield (*Security*) → *Manage roles…*. *New role* (+),
   name it *North only*. Pick **Store** in the table list and type
   `[Region] = "North America"` (the sample's regions are North America, Europe, Asia
   Pacific and Online) in the DAX editor: it completes the table's columns, underlines
   mistakes, and says when the filter isn't a condition on each row: type
   `[Total Sales] > 0` on Product to see *a role filter is a condition on each row…*,
   then *Remove filter*. A filter icon marks the filtered tables. *Members* are a
   free-text list (one per line) kept for Power BI. *Save* commits every change in the
   dialog as one undo step (*Edit roles*).
2. **View as.** *Security* → *View as…*, tick *North only*, *OK*. A banner says
   *Viewing as: North only*. The card drops to North America's sales, the slicer lists
   only North America, and so do filter cards in the Filters pane, tables' totals,
   matrices, highlights, drill-through pages, tooltips and *Export data*: every query
   the report makes carries the role's filters. The role also hides the rows that
   relate to the hidden ones (Sales of other regions' stores), and `ALL` in a measure
   doesn't see past it.
3. **Several roles.** Make a second role, *Europe* (`[Region] = "Europe"`), and view as
   both: the card shows North America plus Europe. Roles combine as a union, as in
   Power BI: per table, the roles' conditions are joined with `||`; a table that one of
   the roles doesn't filter is unrestricted for the union. (For roles filtering
   *different* tables this is wider than Power BI, which unions each role's rows of the
   fact table; documented in `crates/core/src/roles.rs`.)
4. **Stop viewing** in the banner (or *Security* → *Stop viewing*). View as is view
   state: not saved, not undoable, and it ends with the project. The data view shows
   every row and says that View as applies to the report.
5. **Round trips.** *File → Export Power BI project…*: each role is
   `definition/roles/<Role>.tmdl` (`modelPermission: read`, `member …`,
   `tablePermission Store = [Region] = "North America"`), referenced from model.tmdl,
   with charted's id in a `chartedId` annotation. Importing a PBIP (TMDL or model.bim)
   brings roles in; a filter charted can't evaluate (`USERPRINCIPALNAME()`, as in the
   Contoso fixture) comes in and is listed in the import report. The Apache Ossie export
   keeps roles in the model's `POWER_BI` blob as TMSL (`roles[].tablePermissions`), the
   way the official converter does, with charted's ids in the `CHARTED` blob.

## Theme editor and visual styles

1. **Customize.** Add a clustered column chart (Product → Category, Total Sales).
   *Themes* (the palette) → *Customize current theme…*. The editor opens at the side;
   it starts from the report's theme, or from the desktop's colours when the report
   follows Omarchy.
2. **Live preview.** Change *Color 1*: the columns change as you pick. Add, remove and
   reorder data colours; set the page's background, foreground and table accent; set
   fonts, sizes and colours for visual titles, labels and card values (Power BI's
   `title`, `label` and `callout` text classes); turn titles or data labels on or off,
   set the title size (try 24) and the legend position for every visual. Nothing is
   committed yet.
3. **OK** commits the edited theme as one step (*Change theme*); `Ctrl+Z` brings the
   old one back. **Cancel** drops the changes. *Export theme…* writes a Power BI theme
   file that *Browse for themes…* (and Power BI Desktop) can import.
4. **Visual styles from theme files.** Import a theme with `visualStyles` (Power BI's
   `visualStyles[type | "*"]["*"][object][0][property]`): title, legend, category and
   value axes, data labels (`labels`), background, border, the default colour
   (`dataPoint.defaultColor`), line width and markers (`lineStyles`), card values and
   table text sizes become format defaults. They sit between a visual's own formatting
   and the built-in defaults, so the format pane shows them and a visual's own choice
   still wins. Anything else in the file is kept and ignored, and survives PBIP export.

## What-if parameters

1. **New parameter.** Right-click a table (or the space around the tables) in the
   Fields pane → *New parameter…*. Name it *Discount*: *Whole number*, minimum 0,
   maximum 50, increment 5, default 10, with *Add slicer to this page* ticked. A
   maximum below the minimum, an increment of 0 or a default outside the range is
   explained under the boxes, and *OK* waits for it to be fixed.
2. **What it makes**, in one undo step (*New parameter*): a calculated table
   `Discount = GENERATESERIES ( 0, 50, 5 )` whose column is named *Discount*, a measure
   `Discount Value = SELECTEDVALUE ( Discount[Discount], 10 )` in it, and a slicer of
   the values on the page.
3. **Use it.** A card of *Discount Value* shows 10; pick 25 in the slicer and it shows
   25. A measure such as `Total Sales * ( 1 - [Discount Value] / 100 )` follows the
   slicer the same way.
4. **Round trips.** Power BI's own what-if parameters (a GENERATESERIES table whose
   column has `ParameterMetadata`) import as calculated tables, measure included, and
   export as calculated tables (not yet checked in Desktop). Field parameters (NAMEOF
   lists) are still reported as not imported.
