# Milestone 5 checkpoint: the query editor

Run `bin/checkpoint m5`. It builds charted, creates a fresh sample at
`~/Work/charted-checkpoints/Harbor & Pine` (its `data/` folder now also has a messy
`stores_raw.csv` and a `targets.xlsx` workbook), runs the scripted flow in Chromium
(screenshots in `~/Work/charted-checkpoints/m5/`), shows the editor in the real window
(`m5-window-editor.png`), then opens the app with the fresh sample.

Before you start, add a *Slicer* on Store → *Region* to a page, to watch Close & Apply
reach the report.

1. **Open Transform data.** `Ctrl+4`, or the fourth icon in the rail. The queries are on
   the left, the selected step's rows in the middle (the first 1,000), the applied steps
   on the right. Each column header has a type button and a menu of transforms; above the
   rows, each column's profile: quality (valid, error, empty) and distribution (the
   most common values, distinct and unique counts). The strip above shows the step's
   SQL (what DuckDB runs) or the query's M (what Power BI gets).
2. **Get the messy file.** *New source → Text/CSV*, `data/stores_raw.csv`. Like Power
   Query, charted promotes the first row and detects types, which is wrong here: the file
   has two title rows. Delete *Promoted Headers* (the × on the step).
3. **Clean it end to end.**
   - *Reduce rows → Remove top rows*, 2; *Transform → Use first row as headers*.
   - *Remove blank rows*; *Remove duplicates* (HP-006 is in the file twice).
   - Column *store name* ⌄ → *Format text* → *Trim*, then again → *Capitalize Each Word*.
     Do the same for *format* (it has "standard ", "FLAGSHIP").
   - *manager* ⌄ → *Replace values*: leave *Value to find* empty, replace with
     "(vacant)", *Match entire cell contents*.
   - *square feet*: the type button → *Whole number* ("21,000" reads as 21000; values
     that don't convert would show as errors in red in the quality bar).
4. **Split and a conditional column.** *location* ⌄ → *Split column by delimiter*, `, `,
   *Left-most delimiter*: City and Country. *Add column → Conditional column*: *size
   band*, If *square feet* *is greater than or equal to* 24000 Then Large, *Add clause*
   ≥ 12000 Medium, Else Small.
5. **Reorder, delete, undo.** Click an earlier step to see the data as it was then; new
   steps go after the selected one. Drag a step (or focus it and `Alt+↑`) to move it;
   the pencil renames it, the gear edits it, × deletes it. `Ctrl+Z` / `Ctrl+Shift+Z`
   undo and redo in the editor (separately from the report's undo).
6. **Merge with Store.** Untick *Load to report* for stores_raw (it only feeds Store).
   Select *Store*, *Combine → Merge queries*: match *StoreCode* with stores_raw's *store
   code*, add *manager* and *size band*. Then *Region* ⌄ → *Replace values*: North
   America → Americas.
7. **Close & Apply.** charted loads the changed queries (Store, and anything reading it),
   adds the new columns to the model and returns to the report: the slicer now lists
   *Americas*, and the Fields pane has Store → manager and size band. The undo history
   starts again (the data can't be un-loaded), as in Power BI.
8. **Get Data → Excel.** *New source → Excel workbook*, `data/targets.xlsx`: the navigator
   lists the sheets with a preview; tick *Targets 2025* and *Load*. Close & Apply adds the
   table (dates as dates).
9. **A source changes.** Edit `data/stores_raw.csv` in a text editor and save: within a
   few seconds a banner says the source changed, with *Refresh*. Rename or move the file
   and the banner offers *Locate…* instead.

Also there: *Folder* (every CSV in a folder, combined by column name, with Source.Name),
JSON, Parquet, and *SQLite* and *PostgreSQL* databases. Those two need DuckDB's
extensions: the first time, charted asks before downloading them (once, from
extensions.duckdb.org; nothing about your data is sent). PostgreSQL passwords go to your
desktop keyring, never into the project. *Export Power BI project* now writes every step
as M, so the queries work in Power BI too.
